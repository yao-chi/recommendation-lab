# 简历写法：把项目压缩成 3–4 行

> 原则：**一条项目经历 = 一个能力标签**。不要写"我用了什么模型"，要写"我证明了什么"。
> 数字必须能在报告里找到出处，面试官追问时能立刻翻出来。

---

## 推荐使用的版本（3 行，约 150 字）

**2026.11 – 2026.12　两阶段推荐系统：召回 → 排序（MovieLens 100 万条真实评分）**

- **项目背景**：独立搭建召回（流行度 / ItemCF / BPR-MF / 双塔）→ 排序（LR / GBDT / FM / DeepFM）两阶段链路，
  重点验证「离线指标是否可信」，而非堆叠模型。
- **模型与评估**：BPR-MF 全库 Recall@20 **10.94%**（流行度 1.22%、ItemCF 5.34%），
  双塔仅差 1.5 个点但训练成本高 26 倍；排序层 GBDT **AUC 0.8903**，四个模型差距不足 1 个点，
  说明特征工程（召回分数、流派交叉、热度×活跃度）比模型结构更关键。
- **评估诊断（核心贡献）**：设计三组对照实验，量化「随机切分使指标虚高 **87.7%**、
  1:99 负采样使 Recall@20 虚高 **6.1 倍**」，并把全库评估、时间切分、按用户切分写成可复现的评估协议。

## 备选版本（4 行，信息更满，适合一页简历）

**2026.11 – 2026.12　两阶段推荐系统与离线评估可信度研究（PyTorch / scikit-learn）**

- 基于 MovieLens-1M（100 万评分 / 6,040 用户 / 3,706 物品）搭建召回 + 排序链路，全库评估、CPU 可复现。
- 召回：实现 BPR-MF 与双塔（in-batch softmax + logQ 校正 + 固定温度），
  Recall@20 分别 10.94% / 9.45%，并对比曝光多样性（Gini 0.668 / 0.639）。
- 排序：构造 16 维稠密 + 7 类稀疏 + 4 个交叉特征，LR / GBDT / FM / DeepFM 四模型对比，GBDT AUC 0.8903 最优。
- 诊断：三组对照实验证明随机切分虚高 87.7%、负采样虚高 6.1 倍，据此给出统一评估协议。

## 一句话版本（用于自我介绍 / 简历摘要栏）

> 做过一个两阶段推荐系统，最有价值的不是模型，而是我用三组对照实验量化了「离线指标有多少是评估方式造出来的」：
> 随机切分虚高 1.9 倍，负采样虚高 6 倍。

## 不要这么写（反例与原因）

| ❌ 反例 | 为什么不行 | ✅ 改法 |
|---|---|---|
| 使用 BPR、双塔、DeepFM 等多种先进模型 | 只说明会调库，没有判断 | 说清"哪个赢了、赢多少、为什么" |
| 模型准确率达到 95% | 没说是召回还是排序、什么口径 | 写"全库 Recall@20 10.94%" |
| 采用随机划分 8:2 训练测试 | 恰好暴露了评估缺陷 | 写"时间切分 + 全库评估" |
| 提升了推荐效果 | 无数字、无对比 | 写"是流行度基线的 8.9 倍" |
| 熟悉推荐系统全流程 | 空泛 | 写具体环节：召回 / 排序 / 评估 |

## 面试时的展开顺序（配合 `docs/interview-qa.md`）

1. **先讲结构**：两阶段、4+4 个模型、全库评估（30 秒）。
2. **再讲结论**：BPR 10.94%、双塔 9.45% 但贵 26 倍、GBDT AUC 0.89（30 秒）。
3. **重点讲诊断**：随机切分 +87.7%、负采样 ×6.1（这是差异化，1 分钟）。
4. **等追问**：坑（空间不一致 / logQ / 温度坍缩）、冷启动分层、为什么 FM 最差。
